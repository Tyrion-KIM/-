## 九、执行时效与截单管理设计（2026-08-19 修订，V1.1）

### 背景
针对两个落地问题：① 执行时效——审批不能为了形式拖慢实际发货效率；② 尾端发运的截单时间需要统一口径并制定方法。

### 决策记录
1. **强合规模式确认**：审完才能动——所有物理执行（备货/订舱/交运）必须待审批链完成后进行，提效只靠压缩审批耗时，不开"先发后审"口子
2. **截单口径（统一北京时间）**：工厂 16:00（留打包操作时间）/ 海外仓 15:00（15点前下单当日处理）/ 物流收单 15:00（跟随海外仓收单节点收口）/ 申请人最晚提交 13:00（推导值 = 15:00 − Step2/3 SLA 2h）
3. **时效杠杆只做①②**：全链 SLA+超时升级、加急通道；分级短链（③）与并行审批（④）暂不动 11 步链，留待管理层后续评估
4. **倒推法定标**：节点截单时间 = 下游硬截止 − 本节点标准作业时长 − 安全缓冲，四层倒推（外部硬截止 → 执行节点 → 物流收单 → 申请人提交线）

### 新增内容
- 项目书新增 **Section 5《执行时效与截单管理》**（填补原第5章删除后的空位）：
  - 5.1 设计原则（强合规 / SLA倒推定标 / 统一北京时间）
  - 5.2 截单时间基准表（四层倒推，含执行节点绑定说明）
  - 5.3 全链审批 SLA 与超时升级（L1 DING提醒 → L2 升级上级 → L3 错过截单标红；附标准链/加急链两条时间线示例）
  - 5.4 加急通道（理由必填 / SLA减半 / 月度加急率统计防滥用）
  - 5.5 OA 系统时效功能（预计执行日计算 / 停留时长显示 / 超时后果显性化 / 截单基准表维护）
