# 物流中心 DAP 成本模型 — 需求原型文档

## 1. 背景

物流中心需要对海外仓 DAP 条款下的端到端物流成本进行可视化分析，按产品系列（G/M/N）和目的地（德国/美国）对比单台成本结构，支撑定价决策和成本优化。

## 2. 数据源

**物流中心费用汇总表**（在线 Excel），通过 API 导出为 `full_table.json`。

### 2.1 表格结构

| 列 | 字段 | 说明 |
|----|------|------|
| 0 | 运输条款 | FOB / DAP |
| 1 | 货运单位 | 单条柜子（N pcs）/ 单产品（1pcs） |
| 2 | 货物路径 | 工厂→上船 / 工厂→海外仓 |
| 3 | 生产地 | 深圳 / 越南 |
| 4 | 目的国 | 德国 / 美国 |
| 5 | 区域 | C端谷仓 / B端中转 / 美东 / 美西 |
| 6 | 机型 | G系列 / M系列 / N系列 |
| 7 | 内陆运费+报关 | — |
| 8 | 运输费（海运/主运费） | — |
| 9 | 运输费（铁路） | 备选方案 |
| 10 | 运输费（卡航） | 备选方案 |
| 11 | 目的港费用 | — |
| 13 | 海外仓卸柜费用 | C端谷仓 |
| 15 | 海外仓入库清点费用 | B端中转仓 |
| 17 | 仓储成本 | C端谷仓 |
| 18 | 仓储成本 | B端中转仓 |
| 19 | 出库操作费 | B端 |
| 20 | 出库操作费 | C端 |
| 21 | 尾程运费（快递） | C端谷仓 |
| 22 | 尾程运费 | B端中转仓 |
| 23 | 尾程卡车费 | C端谷仓 |
| 24 | 尾程卡车费 | B端中转仓 |
| 25 | 单台成本 | **⚠️ 不使用，值 ≠ A+B+C+D+E** |

### 2.2 数据映射规则（2026-08-04 确认）

每条数据行的 B/C/D/E 费用段根据 `area` 字段取对应列：

```
A(头程) = col[7] + col[8] + col[11]              // 所有路线统一，与area无关
```

| 费用段 | C端谷仓 | B端中转 | 美东 / 美西 |
|--------|---------|---------|-------------|
| B 上架 | col[13] 海外仓卸柜 | col[15] 入库清点 | col[13] 优先，无则 col[15] |
| C 仓储 | col[17] C端仓储 | col[18] B端仓储 | col[17] 优先，无则 col[18] |
| D 出库 | col[20] C端出库 | col[19] B端出库 | col[20] 优先，无则 col[19] |
| E 尾程 | col[21] 快递 | col[24] 卡车 | col[21] 优先，无则 col[24] |

> ⚠️ **关键规则**：
> - C端/B端行：只取对应端的列，另一端列数据均为 `/`（空）
> - 美东/美西行：数据仅存在于 C端列，因此 C端优先取
> - col[8]/col[9]/col[10] 是互斥的运输方式（海运/铁路/卡航），col[8] 是实际使用的主运费
> - **单台成本 = A+B+C+D+E 计算得出，不使用 col[25]**（col[25] 为表格独立公式，值与五段费用之和不同）

## 3. 输出物

### 3.1 成本云图 (`output/成本云图_G系列_M系列.html`)

- **三列布局**：G系列 / M系列 / N系列
- **气泡云图**：A/B/C/D/E 五项费用 SVG 气泡，气泡大小 = 费用占比
- **路线卡片**：按德国/美国分两组，含头程/尾程占比和目的地均值

### 3.2 费用汇报 (`output/物流中心费用_汇报.html`)

- **KPI 卡片**（1行3张）：深圳→德国 / 越南→德国 / 全段目标价 35€（≈275 RMB）
- **目标对比明细表**：按目的地×产品分组，超幅用进度条可视化
- **结论与建议**：德国/美国分组自检分析

### 3.3 成本全景 (`output/物流成本全景.html`) ★ 目标文件

合并云图+汇报的单页全貌：KPI → 目标对比表 → G/M/N云图 → 结论与建议

## 4. 钉钉推送

### 4.1 推送脚本 (`push_cost_report.py`)

```
python push_cost_report.py           # 正式推送
python push_cost_report.py --dry-run # 仅预览
```

- 调用 `build_panorama.build()` 生成完整全景 HTML
- 通过钉钉自定义机器人 Webhook 发送 ActionCard 卡片消息
- 卡片含 KPI 摘要 + 目标对比表 + 结论 + GitHub 下载链接
- 依赖：`../7,8,9,10月发运+收货计划/dingtalk-digest/dingtalk_common.py`

### 4.2 推送调度

- 频率：每月 1 号 9:07（会话 cron，7天过期）
- 换长期：建议 Windows 任务计划程序或 GitHub Actions

### 4.3 HTML 查看

GitHub 不支持 HTML 在线预览（返回 text/plain）。须下载到本地双击打开。
